# iksa — M2a Goal Planner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `iksa ask "<goal>"` queues a natural-language task; `iksa run` drives it step by step with a Claude model that sees a pruned element list, picks one action per turn, and goes through M1's existing gates, audit, snapshots, CAPTCHA pauses and secret handling.

**Architecture:** Three small modules on top of M1. `observe.rs` turns the page into numbered element lines plus a unique CSS selector per element. `llm.rs` is a blocking Anthropic Messages client (`ureq`, run in `spawn_blocking`). `planner.rs` builds each request, validates the one tool call, and maps the chosen element ref to its selector. The rest of the engine is unchanged: a planner step becomes an ordinary `Action` that is appended to the task and executed by the M1 step path. Approval resume, replay, records and redaction work exactly as for scripted tasks.

**Tech Stack:** M1 stack (Rust 1.97, tokio, serde, rusqlite, blake3, zstd, libc, anyhow, thiserror) + `ureq` 3 (HTTPS client, rustls). macOS `security` CLI for the Keychain.

**Spec:** `PRD.md` §1.1 (pillars), §3.2 (planner, page representation, what leaves the machine), §3.5, §3.7. M1 plan: `docs/superpowers/plans/2026-10-28-m1-agent-core-v2.md`. Decisions from the user (2026-11-03): Anthropic first, step-by-step loop, schedule + suggestion inbox go to M2b, two plans.

## Decisions this plan makes

- **The model never sees raw HTML or field values.** It gets one line per interactive or text element (`[7] button "Search"`). `[7]` is a ref valid only for that observation. Before execution iksa maps the ref to a unique CSS selector it computed itself, so records, resume and replay keep working with selectors exactly as in M1.
- **Secrets never reach the model or the database.** The model types `{{secret:NAME}}`. The engine resolves it from the Keychain only at the moment it types, adds the resolved value to `scrub`, and stores the placeholder, never the value.
- **One fresh request per step, not a growing chat.** Each request is the cached system prompt and tools, then one user message holding the goal, a compact log of previous steps, and the current observation. No thinking blocks are replayed, so preserved-thinking rules don't apply. Token use stays roughly flat per step.
- **Model config defaults to none.** Per PRD §3.2, `iksa ask` refuses until `model` is set in `config.json`. The documented example uses `claude-opus-5-5`. The user can pick `claude-sonnet-5-5` or `claude-haiku-5-5` for cost.
- **HTTP client: `ureq` 3.** Shelling out to `curl` would put the API key in the process list (`ps`). `ureq` is small and blocking, so it runs on `spawn_blocking` without adding an async HTTP stack.
- **Refusal fallback on by default** (claude-api skill guidance for `claude-opus-5-5` / `claude-sonnet-5-5`): beta header `server-side-fallback-2026-07-01` + `"fallbacks": "default"`. Config `model.fallbacks: false` turns it off.

## Global Constraints

- Everything in the M1 plan's Global Constraints still holds: binary < 60 MB; step bookkeeping < 25 ms; memory and egress targets; 0700 data dir; launch args; no TCP port; ignored tests must be run before a task is done; tests never write under `target/codex`.
- **Network:** the only new outbound host is the configured model endpoint (default `https://api.anthropic.com`). Tests use a local mock unless the test is `#[ignore]` and named `live_*`.
- **API:** `POST {endpoint}/v1/messages` with headers `x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`, and `anthropic-beta: server-side-fallback-2026-07-01` when fallbacks are on. Body: `model`, `max_tokens: 4096`, `thinking: {type: "adaptive"}`, `output_config: {effort: <config, default "low">}`, `system` (one text block with `cache_control: {type: "ephemeral"}`), `tools` (each `strict: true`, `additionalProperties: false`), `tool_choice: {type: "auto", disable_parallel_tool_use: true}`, `messages`, `fallbacks: "default"`. Never send `temperature`/`top_p`/`top_k`, `budget_tokens`, or forced `tool_choice` (all 400 on current models).
- **Key storage:** `ANTHROPIC_API_KEY` env var if set (tests, CI). Otherwise macOS Keychain service `iksa`, account `anthropic`. Never in `config.json`, never in argv.
- **Secrets:** Keychain service `iksa-secret`, account = name. Placeholder syntax exactly `{{secret:NAME}}`, NAME `[A-Za-z0-9_-]+`.
- **Dependencies:** M1 list + `ureq` (features: `json`, default TLS). Nothing else.

## Review Focus

- **Model calls a ref that doesn't exist, or an unknown tool:** no browser action happens; the error is fed back as the step outcome and the model gets the next turn. 3 invalid calls in a row → `Failed("model kept choosing invalid actions")`. Test `invalid_ref_is_fed_back` (Task 5).
- **Page on a `never_send` domain:** nothing about the page is sent. The task pauses `AwaitingHandoff(Approval)` with outcome `blocked: <host> is on never_send`. Test `never_send_domain_never_reaches_model` (Task 5): the mock server records zero requests.
- **Secret in a goal or typed field:** the model only ever sees `{{secret:NAME}}`; the Keychain value appears in no request body, record, report, snapshot or the DB. Test `secret_placeholder_never_leaves` (Task 5).
- **API 429/529/5xx:** retried up to 3 times, honouring `retry-after` (cap 30 s); then `Failed("model API: <status> <type>")`. 400/401/403 are not retried. Tests `retries_on_429_then_succeeds`, `auth_error_not_retried` (Task 2).
- **Runaway loop:** a hard `max_steps` (config, default 25) ends with `Failed("step budget exhausted")`. Test `step_budget_ends_task` (Task 5).

### Task 1: Page observation

**Files:** Create `src/observe.rs` (JS source as one `const OBSERVE_JS: &str`); `src/lib.rs`; `tests/engine.rs` (fixtures).

**Interfaces:**
- `pub struct Element { pub r#ref: u32, pub line: String, pub selector: String }`.
- `pub struct Observation { pub url: String, pub title: String, pub elements: Vec<Element>, pub text: String }`.
- `pub fn render(o: &Observation) -> String`: `URL: …\nTitle: …\n` + one `line` per element + `\nText:\n` + `text`. Truncated to `MAX_OBSERVATION_CHARS = 12_000` with the marker `…[truncated]`.
- `Engine::observe(&self, b, session) -> anyhow::Result<Observation>` (in `engine.rs`): evaluates `OBSERVE_JS` with `returnByValue`.
- JS rules:
  - **Visible elements only:** non-zero rect, not `visibility:hidden`/`display:none`.
  - **Included:** `a[href]`, `button`, `input`, `select`, `textarea`, `[role=button|link|checkbox|tab|menuitem]`, `[contenteditable]`, plus `h1–h3` as text lines.
  - **Line format:** `[n] <role> "<accessible name ≤80 chars>"`.
  - **Extra attributes:**
    - links: ` → <href path>`;
    - inputs: ` type=<type>`, ` placeholder="…"`, and ` filled` / ` empty`. **Never the value**; passwords are always just `filled`/`empty`.
    - `select`: the option labels, not the selected value.
  - **Selector:** `#id` if the id is unique, else the shortest `tag:nth-of-type(k)` chain from the nearest ancestor with a unique id (or `body`). Verified with `document.querySelectorAll(sel).length === 1`.
  - **`text`:** `document.body.innerText`, whitespace collapsed, ≤ 4,000 chars.
  - Max 200 elements.

### Task 5: Planner loop

**Files:** Create `src/planner.rs`; `src/engine.rs`; `tests/planner.rs`.

**Interfaces:**
- `planner::SYSTEM: &str`. Fixed, cached text that:
  - describes the job;
  - says actions go through risk gates;
  - forbids guessing credentials (use `{{secret:NAME}}` only when the goal names a secret);
  - requires exactly one tool call per turn and `done` when finished.
- `planner::tools() -> serde_json::Value`: `navigate{url}`, `search{query}`, `click{ref, risk: "read"|"write"|"financial"}`, `type{ref, text, secret: bool, risk}`, `extract{ref}`, `done{answer}`. Each has `strict: true`, `additionalProperties: false`, all fields required.
- `planner::user_message(goal, log: &[String], obs: &str) -> String`: `Goal: …\n\nSteps so far:\n- …\n\nCurrent page:\n<render(obs)>`. The log holds one line per step: `<n>. <action summary> → <scrubbed outcome ≤ 200 chars>`.
- `planner::to_action(tool, input, obs) -> Result<Option<Action>, String>`:
  - maps a ref to its selector, a `Err(msg)` meaning "feed back, no browser action";
  - `done` → `Ok(None)`;
  - the model's `risk` is a floor: iksa uses `max(model_risk, Write)` for `click`/`type` unless the model says `financial`, so the model can raise risk but never lower it below Write.
- Engine: `run` on a task with `goal` loops until `max_steps`:
  1. Observe. If the host matches `never_send` → `AwaitingHandoff(Approval)`, recording outcome `blocked: <host> is on never_send`, and send nothing.
  2. Build the body, store it in the CAS, then `llm::call` on `spawn_blocking`.
  3. `to_action`:
     - `Err`: record outcome `invalid: …`, invalid streak + 1 (3 → `Failed`).
     - `Ok(None)`: record `done: <answer>`, then `Committed`.
     - `Ok(Some(a))`: `push_step`, then run it through the M1 single-step path (gate, record with `thought` + `model_request`, snapshot rules, challenge).
  4. An approval or challenge pause returns as in M1. Resume works because steps are ordinary selector actions: on resume the engine replays as M1 does and then continues the loop.
- `scrub` covers resolved secrets, and the goal text is scrubbed before it's sent if it contains a resolved secret.
